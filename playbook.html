Один принцип за всеми решениямиOne principle behind every decisionUm princípio por trás de cada decisão

На каждом шаге этого гида мы задавали один и тот же вопрос: даёт ли эта архитектура человеку, для которого она работает, возможность сказать «стоп», пока это ещё важно? Отсюда — человек в контуре для необратимых действий, внешний судья вместо доверия агенту оценивать себя, простота по умолчанию.

At every decision in this guide we asked the same thing: does this architecture give the human it works for a way to say "stop" while it still matters? Hence — human in the loop for irreversible actions, an external judge instead of trusting the agent with itself, simplicity over complexity by default.

Em cada decisão deste guia perguntamos o mesmo: esta arquitetura amplia a agência humana ou a substitui? Se amplia — entra no playbook; se substitui — fica de fora, por mais elegante que seja a tecnologia.

Что такое агент простыми словамиWhat is an agent, in plain wordsO que é um agente, em palavras simples

Агент — это цикл: LLM получает задачу → выбирает инструмент → получает результат → рассуждает дальше → повторяет до получения ответа. Всё остальное надстраивается над этим циклом.

An agent is a loop: the LLM gets a task → picks a tool → receives the result → reasons further → repeats until the answer. Everything else is built on top of this loop.

Um agente é um loop: o LLM recebe uma tarefa → escolhe uma ferramenta → recebe o resultado → raciocina adiante → repete até a resposta. Todo o resto é construído sobre esse loop.

Pythonagent.py
import json, os
from openai import OpenAI
client = OpenAI(
    api_key=os.getenv("OPENAI_API_KEY", "ollama"),
    base_url=os.getenv("OPENAI_BASE_URL", "https://api.openai.com/v1"),
)
MODEL = os.getenv("AGENT_MODEL", "gpt-4o-mini")

def get_weather(city: str) -> str:
    """Возвращает погоду из тестового API."""
    return f"{city}: +21°C, солнечно"

TOOLS = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "Получить погоду по городу",
        "parameters": {
            "type": "object",
            "properties": {"city": {"type": "string"}},
            "required": ["city"],
        },
    },
}]

def run_agent(user_input: str, max_steps: int = 5) -> str:
    messages = [
        {"role": "system", "content": "Ты полезный ассистент. Отвечай кратко и по делу."},
        {"role": "user", "content": user_input},
    ]
    for _ in range(max_steps):                    # защита от бесконечного цикла
        resp = client.chat.completions.create(model=MODEL, messages=messages, tools=TOOLS)
        msg = resp.choices[0].message
        if not msg.tool_calls:                    # готовый ответ
            return msg.content
        messages.append(msg)
        for call in msg.tool_calls:               # выполняем все вызовы инструментов
            args = json.loads(call.function.arguments)
            messages.append({
                "role": "tool",
                "tool_call_id": call.id,
                "content": str(get_weather(**args)),
            })
    return "Лимит исчерпан: максимальное число шагов"

if __name__ == "__main__":
    print(run_agent("Какая погода в Амстердаме?"))

Pythontools.py
TOOL_FUNCS = {"get_weather": get_weather}   # добавляйте свои инструменты сюда

def dispatch(call) -> str:
    fn = TOOL_FUNCS.get(call.function.name)
    if fn is None:
        return f"Ошибка: неизвестный инструмент {call.function.name}"
    try:
        return str(fn(**json.loads(call.function.arguments)))
    except TypeError as exc:
        return f"Ошибка аргументов: {exc}. Проверьте JSON-схему параметров."
    except Exception as exc:
        return f"Ошибка выполнения: {exc}"

Memory: compressing long history

Pythonmemory.py
def compress_history(messages, keep_last=6):
    if len(messages) <= keep_last:
        return messages
    old = messages[:-keep_last]
    summary = client.chat.completions.create(
        model=MODEL,
        messages=[{"role": "user",
                   "content": "Сожми следующую историю:\n" + json.dumps(old, ensure_ascii=False)}],
    ).choices[0].message.content
    return ([{"role": "system", "content": f"Краткое содержание истории: {summary}"}]
            + messages[-keep_last:])

Трассировка: видно каждый шаг

Tracing: see every step

Rastreamento: veja cada passo

Pythontracing.py
import time, uuid, functools, json, contextvars
# для нового запуска: CURRENT_TRACE.set(str(uuid.uuid4()))
CURRENT_TRACE = contextvars.ContextVar("trace", default=str(uuid.uuid4()))

def traced(name):
    def deco(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            span = {"trace_id": CURRENT_TRACE.get(), "step": name, "start": time.time()}
            try:
                out = fn(*args, **kwargs); span["status"] = "ok"; return out
            except Exception as exc:
                span["status"] = "error"; span["error"] = str(exc); raise
            finally:
                span["ms"] = round((time.time() - span["start"]) * 1000)
                print(json.dumps(span, ensure_ascii=False))
        return wrapper
    return deco

@traced("tool.get_weather")
def get_weather(city: str) -> str:
    return f"{city}: +21°C, солнечно"

Инструменты и память: правила

Tools & memory: rules

Ferramentas e memória: regras

  • Один инструмент — одно действие. create_issue и close_issue, а не manage_issue.
  • Описания пишутся для LLM: когда вызывать и какие ограничения.
  • Идемпотентность: повторный вызов не должен портить состояние.
  • Ошибки возвращаются как текст, а не как продакшен-исключения.
  • Память: рабочая — messages[] + сжатие; эпизодическая — векторный поиск; семантическая — RAG; процедурная — кэши «что сработало».
  • One tool — one action. create_issue and close_issue, not manage_issue.
  • Uma ferramenta — uma ação. create_issue e close_issue, não manage_issue.
  • Descriptions are for the LLM: when to call and the constraints.
  • As descrições são para o LLM: quando chamar e quais as restrições.
  • Idempotency: repeating a call must not corrupt state.
  • Idempotência: repetir uma chamada não deve corromper o estado.
  • Errors go back as text, not as production exceptions.
  • Erros voltam como texto, não como exceções de produção.
  • Memory: working — messages[] + compression; episodic — vector search; semantic — RAG; procedural — "what worked" caches.
  • Memória: de trabalho — messages[] + compressão; episódica — busca vetorial; semântica — RAG; procedural — caches do "que funcionou".
MCP (Model Context Protocol)

Открытый стандарт для инструментов и данных — «USB-C для LLM». Один сервер инструментов переиспользуется агентами и IDE.

An open standard for tools and data — "USB-C for LLMs". One tool server is reused by agents and IDEs.

Um padrão aberto para ferramentas e dados — "USB-C para LLMs". Um servidor de ferramentas é reutilizado por agentes e IDEs.

def input_guardrail(text: str) -> str:
    lowered = text.lower()
    for p in DENY_PATTERNS:
        if p in lowered:

class BudgetGuard:
    def __init__(self, max_usd=1.0):
        self.spent, self.max = 0.0, max_usd
    def charge(self, usage, in_price=0.00015, out_price=0.0006):
        self.spent += (usage.prompt_tokens / 1000 * in_price
                       + usage.completion_tokens / 1000 * out_price)
        if self.spent > self.max:

  • Агент удаляет production-данные. Публичный кейс (июль 2025): агент в облачной IDE удалил production-БД при «штатной» задаче. Корень — избыточные права, никакого подтверждения.

  • Agent deletes production data. Public case (July 2025): a cloud-IDE agent deleted a production DB during a "routine" task. Root — excessive rights, no confirmation.
  • Agente apaga dados de produção. Caso público (julho de 2025): um agente de IDE em nuvem apagou um banco de produção durante uma tarefa "de rotina". Causa — permissões excessivas, sem confirmação.
  • Injection via documents. Hidden instructions in PDFs and pages get executed by agents with mail/file access.
  • Injeção via documentos. Instruções ocultas em PDFs e páginas são executadas por agentes com acesso a e-mail/arquivos.
  • Silent leaks. Sensitive data lands in logs and analytics because "nobody forbade it".
  • Vazamentos silenciosos. Dados sensíveis vão parar em logs e analytics porque "ninguém proibiu".

Quando você precisa de isolamento de contexto, subtarefas paralelas, modelos diferentes por etapa. Caso contrário, um agente com boas ferramentas é mais barato e confiável.

Отсюда — простота по умолчанию, человек в контуре, внешний судья вместо самооценки.Philosophy. We build partners, not "smart machines". Every pattern in this guide is tested by one question: does the human keep their choice and the ability to say "stop"? An agent system is good when it expands the freedom of the person using it, instead of replacing their decisions. Hence — simplicity by default, human in the loop, an external judge instead of self-evaluation.Filosofia. Construímos parceiros, não "máquinas inteligentes". Cada padrão deste guia é testado por uma pergunta: o humano mantém sua escolha e a capacidade de dizer "pare"? Um sistema de agentes é bom quando amplia a liberdade de quem o usa, em vez de substituir suas decisões. Daí — simplicidade por padrão, humano no loop, um juiz externo em vez de autoavaliação.
